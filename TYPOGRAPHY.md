# Глобальные правила типографики и переносов

Примени эти правила ко **всей странице MVP-портфолио** и ко всем элементам, которые будут добавляться в дальнейшем.

Правила обязательны для заголовков, описаний, карточек, тегов, кнопок, ссылок, подписей и любого другого текстового контента.

## 1. Неразрывные пробелы

Не допускай появления висячих предлогов, союзов и частиц в конце строки.

Используй неразрывный пробел (`\u00A0`) между коротким служебным словом и следующим за ним словом.

Примеры:
- `в работе` → `в работе`
- `и проекты` → `и проекты`
- `на сайте` → `на сайте`
- `с командой` → `с командой`
- `не только` → `не только`
- `а ещё` → `а ещё`
- `по работе` → `по работе`
- `у меня` → `у меня`

Учитывай односложные и короткие предлоги, союзы, частицы: «в», «с», «к», «у», «о», «а», «и», «но», «на», «за», «по», «не», «ни», «же», «бы», «ли» и другие.

Не заменяй все обычные пробелы неразрывными. Связывай только те слова, между которыми перенос нарушает правила типографики или ухудшает читаемость.

## 2. Дефисные слова и выражения

Слова и выражения, написанные через дефис, должны переноситься **целиком на следующую строку**, если не помещаются в текущей.

Примеры:
- `по-хорошему`
- `как-то`
- `что-то`
- `кто-нибудь`
- `всё-таки`
- `из-за`
- `по-прежнему`
- `B2B-продукты`

Запрещено оставлять одну часть дефисного слова на предыдущей строке, а другую переносить на следующую.

Для этого используй неразрывный дефис (`\u2011`) там, где это необходимо, либо CSS-механизмы, сохраняющие написание и запрещающие разрыв.

Визуально дефис должен оставаться привычным.

## 3. Запрет автоматических переносов внутри слов

Не допускай автоматического разбиения слов по слогам.

Например, слово «портфолио» не должно отображаться как:

`портфо-`
`лио`

Если слово не помещается в строку, оно должно целиком переходить на следующую.

Используй:

```css
html {
  hyphens: none;
  -webkit-hyphens: none;
}

body {
  overflow-wrap: normal;
  word-break: normal;
}
```

Не используй `word-break: break-all` или `overflow-wrap: anywhere` для обычного текста.

Для очень длинных технических строк, например URL, допускается отдельная обработка, чтобы они не ломали адаптивную сетку.

## 4. Заголовки и смысловые группы

Следи не только за техническими переносами, но и за визуальной композицией текста.

- Не разрывай устойчивые выражения.
- Не оставляй короткие служебные слова в конце строки.
- Не допускай одиночного короткого слова на последней строке заголовка, если это ухудшает композицию.
- Сохраняй смысловые группы слов.
- Не меняй формулировки ради переноса без необходимости.
- Не добавляй принудительные переносы строк без причины.

Для крупных заголовков допускаются осознанные ручные переносы, если они предусмотрены дизайном Figma.

При адаптации под другие разрешения пересматривай переносы, чтобы они оставались естественными.

## 5. Типографика

Используй локальные шрифты:
- **Unbounded** — заголовки, крупные акценты
- **Manrope** — основной и вспомогательный текст

Сохраняй размеры, начертания, межстрочные интервалы и межбуквенные расстояния согласно Figma.

Дополнительные правила:
- Используй «ёлочки» для русских кавычек.
- Используй букву «ё» там, где она необходима.
- Различай дефис `-` и тире `—`.
- Не заменяй тире дефисом.
- Для диапазонов используй корректное тире `–`.
- Между числом и единицей измерения используй неразрывный пробел: `6 лет`, `16 px`, `100 %`.
- Не допускай разрыва инициалов и фамилий, если такие конструкции появятся.
- Не ставь точку в конце последнего абзаца текстового блока, если она не требуется по смыслу и это соответствует стилистике страницы.

## 6. Применение в коде

Создай единый механизм обработки типографики, который можно переиспользовать во всех компонентах.

Важно:
- Не расставляй неразрывные пробелы вручную в десятках компонентов.
- Предусмотри утилиту для обработки русского текста.
- Обрабатывай текстовые узлы, не изменяя HTML-разметку, ссылки, атрибуты и код.
- Не изменяй URL, пути к файлам, CSS-классы, технические идентификаторы и программные выражения.
- Не допускай повторной обработки, которая может повредить текст.
- Не применяй автоматические замены к пользовательскому вводу.
- Для дефисных слов сохраняй корректное исходное написание и запрещай разрыв при отображении.

CSS должен дополнять типографическую обработку, а не заменять её.

## 7. Проверка

После реализации проверь все текстовые элементы на десктопе, планшете и мобильных разрешениях.

Особенно проверь:
- Висячие предлоги, союзы и частицы
- Разрывы дефисных слов
- Автоматические переносы по слогам
- Одиночные слова в последней строке заголовков
- Выход текста за границы карточек
- Наложение текста на соседние элементы
- Корректность переноса при изменении ширины окна

**Главное правило: текст должен адаптироваться к ширине контейнера, сохраняя целостность слов, смысловых конструкций и аккуратную композицию.**

Эти требования считай постоянными правилами проекта. Применяй их автоматически ко всем существующим и новым текстовым компонентам, без дополнительных напоминаний.
